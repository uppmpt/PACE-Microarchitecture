# PACE Top-Level Interfaces

Short datasheet for the top-level RTL entry points in `pace_rtl/`.

## 1. Scope

This document describes the externally visible interfaces of the top-level modules currently present in `pace_rtl/`:

- `top_pace.v`
- `top_pace_cache.v`
- `top_pace_final.v`
- `top_pace_full.v`
- `top_pace_imem.v`
- `top_pace_mem.v`
- `top_simple.v`

It also documents `pace_core.v`, which is a Verilog compilation/include file rather than a module.

**Important:** the repository currently contains several top-level variants with substantially different interfaces. The RTL reviewed here does not explicitly identify one variant as the single recommended entry point, nor does it label the others as legacy or experimental. This document therefore describes each variant as it exists rather than assigning a project-level status that is not stated by the RTL.

---

## 2. Common conventions

All top-level modules use Verilog-2001 style `input wire`/`output wire` ports.

The reset signals are named `rst_n`, `rst_n_in`, `rst_n_pcu`, or `rst_n_ao` and are therefore active-low by naming convention. Where a top-level generates internal resets through `boot_sequencer`, this document describes the externally visible reset connection and does not infer additional reset timing behavior that is not established by the top-level RTL.

Most data, address, and debug values are 64 bits wide. Instruction inputs are 32 bits per instruction unless otherwise noted.

# 3. `top_pace`

## 3.1 Overview

`top_pace` is a simpler integration of:

- `pcu`
- `m_core`
- `shadow_rf`
- `b_core`
- `ao_core_pace`
- `register_file`

The PCU and AO-Core use separate reset inputs. The external environment supplies instructions for the PCU and AO-Core and receives a simple M-Core memory interface.

## 3.2 Parameters

`top_pace` has no top-level parameters.

Internal configuration:

| Instance | Parameter | Value | Meaning |
|---|---|---:|---|
| `u_shadow` | `DEPTH` | 32 | Shadow-RF depth |
| `u_shadow` | `DATA_WIDTH` | 64 | Shadow-RF entry width |
| `u_arf` | `DATA_WIDTH` | 64 | Architectural RF data width |
| `u_arf` | `ADDR_WIDTH` | 5 | Architectural RF address width |

These are fixed in `top_pace.v`.

## 3.3 Clock and reset

| Signal | Direction | Width | Description |
|---|---|---:|---|
| `clk` | in | 1 | Common clock |
| `rst_n_pcu` | in | 1 | Reset supplied to PCU-side blocks: PCU, M-Core, Shadow RF, and B-Core |
| `rst_n_ao` | in | 1 | Reset supplied to AO-Core and architectural register file |

## 3.4 Instruction interface

| Signal | Direction | Width | Description |
|---|---|---:|---|
| `pcu_pc` | out | 64 | PC generated by the PCU |
| `pcu_instr` | in | 32 | Instruction supplied to the PCU for `pcu_pc` |
| `ao_pc` | out | 64 | PC generated by the AO-Core |
| `ao_instr` | in | 32 | Instruction supplied to the AO-Core for `ao_pc` |

The top-level provides no explicit instruction ready/valid or latency signal.

## 3.5 Data-memory interface

| Signal | Direction | Width | Description |
|---|---|---:|---|
| `mc_mem_req` | out | 1 | M-Core memory request |
| `mc_mem_we` | out | 1 | Write-enable indication |
| `mc_mem_addr` | out | 64 | M-Core memory address |
| `mc_mem_wdata` | out | 64 | M-Core write data |
| `mc_mem_rdata` | in | 64 | Memory read data |
| `mc_mem_ready` | in | 1 | Memory response/ready indication |

The top-level passes these signals directly between `m_core` and the external environment.

## 3.6 Debug interface

| Signal | Direction | Width | Description |
|---|---|---:|---|
| `dbg_rs` | in | 5 | Architectural register index used by the debug read ports |
| `dbg_arch_rd` | out | 64 | Architectural register-file debug value |
| `dbg_pcu_rd` | out | 64 | PCU debug result |
| `dbg_mc_rd` | out | 64 | M-Core debug value |

## 3.7 Internal connectivity

- PCU shadow writes and M-Core shadow writes are merged before entering `shadow_rf`.
- When both shadow-write enables are asserted, the top-level mux selects the M-Core destination/data.
- PCU and M-Core each receive the other block's shadow write as `ext_wr_*`.
- `pcu_stalled` is tied low at the AO-Core.
- The architectural register file's normal `rs1`/`rs2` read addresses are tied to zero and its normal read outputs are left unconnected; the exposed read path is the debug port.

### RTL compatibility note

The current `top_pace.v` connects `busy` and `pc_out` ports on `m_core`. The separately supplied `m_core.v` interface should be checked against this integration before treating `top_pace` as a standalone compilable top-level. This document intentionally does not change the RTL.

## 3.8 Typical usage

The external environment must provide:

1. `clk` and the two reset signals.
2. Instructions corresponding to `pcu_pc` and `ao_pc`.
3. A memory implementation responding to the `mc_mem_*` interface.
4. A register index on `dbg_rs` if architectural/PCU/M-Core debug reads are required.

Example:

```verilog
top_pace dut (
    .clk(clk),
    .rst_n_pcu(rst_n_pcu),
    .rst_n_ao(rst_n_ao),
    .pcu_pc(pcu_pc),
    .pcu_instr(pcu_instr),
    .ao_pc(ao_pc),
    .ao_instr(ao_instr),
    .mc_mem_req(mc_mem_req),
    .mc_mem_we(mc_mem_we),
    .mc_mem_addr(mc_mem_addr),
    .mc_mem_wdata(mc_mem_wdata),
    .mc_mem_rdata(mc_mem_rdata),
    .mc_mem_ready(mc_mem_ready),
    .dbg_rs(dbg_rs),
    .dbg_arch_rd(dbg_arch_rd),
    .dbg_pcu_rd(dbg_pcu_rd),
    .dbg_mc_rd(dbg_mc_rd)
);
```

# 4. `top_pace_cache`

## 4.1 Overview

`top_pace_cache` integrates the PCU/M-Core path with L1 instruction/data caches and an L2 cache. It exposes external DRAM and uncached MMIO interfaces and provides several internal debug signals.

- `l1d` for data access
- `l2` as the shared backing cache
- `shadow_rf` with 72-bit entries

# 5. `top_pace_final`

## 5.1 Overview

`top_pace_final` is a cache/MMU-oriented top-level with:

- PCU
- M-Core
- Shadow RF
- AO-Core FIFO
- L1 instruction cache with MMU
- L1 data cache with MMU
- L2
- Sv39-related PTE traffic
- external DRAM
- external MMIO
- machine/supervisor interrupt inputs

The current RTL hard-codes the MMU configuration to bare mode:

```verilog
satp_enable = 1'b0;
satp_ppn    = 44'd0;
asid        = 9'd0;
flush_tlb   = 1'b0;
```

# 9. `top_simple`

## 9.1 Overview

`top_simple` is a minimal test/integration top described by the source as:

- 6-wide PCU
- multi-entry Shadow RF
- four AO cores
- combinational instruction memory managed by the testbench

Only lane 0 receives the external instruction; the other five PCU lanes are filled with the 32-bit NOP `32'h00000013`.

The top-level also instantiates a boot sequencer.

## 9.2 Parameters

`top_simple` has no top-level parameters.

The internal boot sequencer uses:

| Parameter | Value |
|---|---:|
| `SCOUT_AHEAD_CYCLES` | 16 |

The Shadow RF is configured with:

| Parameter | Value |
|---|---:|
| `DEPTH` | 32 |
| `DATA_WIDTH` | 72 |
| `N_READ` | 4 |
| `N_WRITE` | 6 |

The AO-core array uses `N_AO = 4`.

## 9.3 Clock/reset

| Signal | Direction | Width |
|---|---|---:|
| `clk` | in | 1 |
| `rst_n` | in | 1 |

`rst_n` is passed into the boot sequencer, which generates separate PCU and AO resets.

## 9.4 Instruction memory

| Signal | Direction | Width | Description |
|---|---|---:|---|
| `imem_addr` | out | 64 | PCU program counter / instruction-memory address |
| `imem_rdata` | in | 32 | External instruction word |

The source comments the instruction-memory interface as combinational and testbench-managed.

The internal instruction bus is:

```verilog

```

so the external instruction occupies lane 0.

# 10. `pace_core.v`

## 10.1 Important distinction

`pace_core.v` does **not** declare a Verilog module and therefore has:

- no ports
- no top-level parameters
- no clock/reset interface of its own

It is a compilation/include file containing `` `include `` directives for the RTL source tree.

## 10.3 Compilation note

Because these sources are brought in using Verilog `` `include ``, compiling the included files separately in addition to the master file can cause duplicate module definitions.

A build should select an actual top-level module such as `top_pace_imem` or `top_pace_mem`; `pace_core.v` itself is not the simulation top.

Notably, `top_pace.v`, `top_pace_cache.v`, `top_pace_final.v`, `top_pace_full.v`, and `top_simple.v` are not included by the supplied `pace_core.v`.

# 11. Interface relationships

The major interface patterns visible across the top-levels are:

```text
Instruction path:
External IMem / L1I
        |
        v
      PCU
        |
        +----> Branch core
        |
        +----> Shadow RF ----> AO core(s) ----> Architectural RF
        |
        +----> Memory queue / M-Core
                              |
                              v
                       L1D / MMU / L2
                              |
                              v
                            DRAM
```

Additional external paths include:

```text
CPU/MMU --------------------> MMIO
CPU ------------------------> AMO extension
CPU ------------------------> Vector memory
CPU/MMU --------------------> PTE memory
External interrupt sources --> PCU
Debug inputs/outputs <------> top-level
```

The exact paths differ between the top-level variants; the diagram is therefore conceptual rather than a statement that every top implements every path.

# 12. Known RTL/interface notes

The following points are worth keeping visible to integrators rather than silently assuming behavior:

1. **`top_pace.v` / `m_core` interface:** the supplied `top_pace.v` connects `busy` and `pc_out` on `m_core`. The current `m_core.v` interface should be reconciled with this integration before treating `top_pace` as a standalone compilable top.

2. **Different top-level generations:** the repository contains both the simpler `pcu`/`shadow_rf`/`ao_core_pace` style and the newer `pcu6_v`/multi-AO/multi-shadow style. The RTL does not explicitly label the variants as legacy, experimental, or recommended.

3. **MMU configuration varies by top:** some variants hard-code bare-mode values while others obtain `satp`/privilege information from the PCU debug path.

4. **Instruction-fetch interfaces differ:** some variants expose one 32-bit instruction, while others expose six 32-bit instruction slots.

5. **Memory widths differ:** simple data-memory interfaces are 64-bit, while backing DRAM interfaces are 512-bit.

6. **`top_simple` is intentionally minimal:** only the first of six PCU instruction lanes is supplied by the external interface; the remaining lanes are filled with NOPs.

7. **`pace_core.v` is not a module:** it is a source-inclusion/compilation file and therefore does not itself have a port-level interface.
